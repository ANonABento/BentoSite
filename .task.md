## Scope

### 4A — Cards become real anchors AND deep-link works
Currently `/projects` and `/playground` cards are `<button>` with onClick handlers. Convert to `<a href>` (or Next.js `<Link>`) so middle-click-to-open-in-new-tab, right-click → Copy Link, prefetch, and crawler indexing all work natively.

**Per the user**: project cards target `/?project=<slug>` is intentional — projects are supposed to render their info on the home dashboard via a deep link. Currently the deep link is a no-op (lands on dashboard with nothing rendered). **Implement the deep link**: when `?project=<slug>` is set on `/`, the home dashboard should render that project's info inline (use existing project data from `src/content/portfolio.json` or wherever projects are sourced — discover the existing structure). Pick the most natural placement on the dashboard (e.g. in the chat panel, a side drawer, or replacing the default 3D viewer content) — match the existing dashboard architecture rather than inventing new chrome.

For `/playground` cards, target the existing game routes (`/playground/2048`, `/playground/minesweeper`, etc.) — the route map exists in JS click handlers today; just make the `<a href>` mirror it.

### 4B — Filter chip horizontal overflow scroll
The OS-chrome floating control panel on `/projects` and `/playground` clips its filter chips. Only the first ~4 are visible. **User chose horizontal scroll** (panel must NOT grow taller — keep the chat panel from getting squashed).

Implement: `overflow-x-auto` + `flex-nowrap` on the chip strip, with a right-edge fade indicator (CSS gradient mask) hinting more content. Optional: scroll-snap on chip width for nice paging. No vertical wrap.

### 4C — Search card → "Info card" refactor
The grid pages have a "search card" (per `docs/bentogrid-handoff.md`). **User wants it renamed to "info card" (or similar)** and made the consolidation point for all overlay info + help affordances:

1. **Rename the component** (search card → info card or similar). Update imports, tests, types, doc references.
2. **Consolidate overlays into tooltips inside the info card**:
   - The pan/zoom hint (currently only in `aria-label`: `Use arrow keys to focus cards, Enter to open, WASD to pan, R to reset view`) becomes a visible tooltip/popover triggered from a (?) icon inside the info card.
   - The debug HUD (`Camera (0,0) z:1.00 / Visible / Queue`) — **already gated behind `?debug=1` in PR #67** — when active, render its data INSIDE the info card as a tooltip/section, not as a free-floating bottom-left overlay.
   - Any other ambient grid affordances should consolidate here instead of floating around the canvas.
3. **Keep search functionality** (assume it has search; preserve that capability — don't break what's there).

## Acceptance criteria
- `/projects` cards: middle-click opens `/?project=<slug>` in new tab; right-click shows "Copy Link Address"; clicking the card (left-click) navigates to `/?project=<slug>` AND the home dashboard renders that project's info on arrival.
- `/playground` cards: middle-click opens the correct game route in new tab; left-click navigates SPA-style.
- Filter chip strip: all categories accessible via horizontal scroll; right-edge fade indicator visible when more content exists; panel height unchanged.
- Info card present on `/projects` and `/playground` with consolidated overlays; pan/zoom hint visible to mouse users (not just screen readers).
- Debug HUD at `?debug=1` renders inside the info card, not as floating bottom-left.
- `npm run lint` clean. `npm run type-check` clean (or `npx tsc --noEmit`). Vitest passes.
- Visual verification with screenshots in `docs/visual-audit-assets/2026-05-03/after-t4/` for: cards in light + dark, chip overflow scroll state, info card with tooltip open, debug HUD inside info card.
