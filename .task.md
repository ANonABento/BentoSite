# Implementation Plan: Split `Chat.tsx` and `app/scrollable/page.tsx`

## Summary

This task is a pure refactor. The goal is to bring `src/components/Chat.tsx` and `src/app/scrollable/page.tsx` back under the project’s file-size and single-responsibility conventions without changing behavior, public APIs, visual output, persistence shape, or runtime wiring.

The plan below is based on:

- `CLAUDE.md`
- `split-chat-and-scrollable.task.md`
- the current implementations of `src/components/Chat.tsx`, `src/app/scrollable/page.tsx`, `src/components/ui/ErrorBoundary.tsx`
- the existing modular patterns in `src/components/Dimension/` and the current dashboard/page composition

## Constraints To Preserve

- Keep `@/components/Chat` as the import path and keep the default export.
- Do not change the localStorage schema for `STORAGE_KEYS.CHAT_HISTORY`.
- Do not change `/api/chat` or `/api/feedback` request/response handling.
- Do not change scrollable-page UX, hero composition, chat-panel behavior, or animation semantics.
- Do not add dependencies.
- Do not fold unrelated cleanups into this refactor.

## Key Risks Found During Codebase Review

### 1. `@/components/Chat` is currently a file, but the target shape is a folder

This is the main migration hazard.

Today:

- `src/components/Chat.tsx`

Target:

- `src/components/Chat/Chat.tsx`
- `src/components/Chat/index.ts`

The file and folder cannot coexist at the same path. That means the migration must be staged carefully:

1. Extract helpers and parts first while the old `src/components/Chat.tsx` still exists.
2. In one final move step, delete `src/components/Chat.tsx` and create the `src/components/Chat/` folder with `index.ts` and `Chat.tsx`.

Avoid any intermediate state where both are expected to exist.

### 2. Replacing the inline scrollable-page error boundary can silently change the UI

`src/app/scrollable/page.tsx` currently ships its own inline fallback UI.

`src/components/ui/ErrorBoundary.tsx` supports `fallback`, but its default button styling uses hardcoded Tailwind violet classes:

- `bg-violet-500`
- `hover:bg-violet-400`
- `active:bg-violet-600`

That means switching to the shared component without passing an explicit fallback would create a visual change and violate the refactor-only constraint.

Plan implication:

- remove the inline class boundary
- keep the current visual fallback by passing a dedicated fallback component or inline JSX into the shared boundary
- do not rely on the shared default fallback for this refactor

### 3. Dynamic import boundaries should remain page-owned where chunking matters

The current `scrollable/page.tsx` defines dynamic imports at the route level. Moving those `dynamic()` calls into extracted child components can create different chunk boundaries and subtly change load behavior.

Plan implication:

- keep heavy route-level dynamic shells in `page.tsx`
- pass dynamically loaded components into extracted layout parts as props when needed

### 4. `isMountedRef` is used to coordinate delayed chat sends

Both `scrollable/page.tsx` and `DashboardLayout.tsx` use mounted refs around delayed chat actions. The extracted `useScrollableLayout` hook needs to remain the source of truth for that page-level delayed interaction.

```text
src/app/scrollable/
├── page.tsx
├── hooks/
│   └── useScrollableLayout.ts

    ├── HeroSection.tsx
```

`ScrollableErrorFallback.tsx` is recommended even though the task description lists only five extracted page parts. It keeps the error UI stable while still removing the inline class boundary from `page.tsx`.

Verification after this phase:

- `npm run lint`

### Phase 2: Extract Chat hooks

Create:

- `src/components/Chat/Chat.hooks.ts`

Split responsibilities into two hooks:

1. `useChatMessages`
2. `useChatSubmit`

`useChatMessages` should own:

- `messages`
- hydration/load effect
- save effect gated by hydration
- `messagesEndRef`

- `addAssistantMessage`
- `clearChat`

`useChatSubmit` should own:

- `input`
- `isLoading`
- `error`
- `isDemoMode`
- `sendMessage`
- `handleFeedback`

Critical implementation detail:

- preserve the current functional `setMessages` resolver Promise pattern inside `sendMessage`
- do not rewrite that logic to use plain closure state

Verification after this phase:

- `npm run type-check`
- `npm run lint`
- `npm test`

### Phase 3: Extract Chat UI parts

Create:

- `src/components/Chat/parts/CopyButton.tsx`

Verification after this phase:

After extraction, `page.tsx` should mainly own:

- route-level dynamic imports

Target:

## Acceptance Criteria

- No behavioral change in chat or scrollable page.
- `src/components/Chat.tsx` is replaced by a folder-based `src/components/Chat/index.ts` public entry.
- All existing `@/components/Chat` imports remain unchanged and working.
- `src/app/scrollable/page.tsx` is reduced to a composition shell.
- The inline scrollable-page `ErrorBoundary` class is removed.
- Shared `ErrorBoundary` is used with an explicit fallback to preserve current UI.
- `type-check`, `lint`, `test`, and `build` pass.
- Any new files stay within the repo’s modular conventions and remain comfortably under 300 lines.

## Decisions To Lock Before Implementation

1. Use route-local parts under `src/app/scrollable/layout-parts/`, not shared `src/components/Scrollable/`.
2. Keep dynamic imports route-owned unless there is a strong reason to move them.
3. Preserve scrollable-page error UI by passing a custom fallback into the shared `ErrorBoundary`.
4. Perform the Chat file-to-folder swap only in a final dedicated move step.

## Out Of Scope

- Refactoring `Dimension.3d.tsx` or any other oversized file.
- Converting footer SVGs to shared icon components.
- Reworking chat UX or API handling.
- Opportunistic styling cleanups in the shared `ErrorBoundary`.
