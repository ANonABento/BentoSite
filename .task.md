# Implementation Plan: Finish Chat and Scrollable Page Split

## Task

Refactor the oversized Chat and `/scrollable` page code into smaller responsibility-focused modules without changing behavior, public imports, persisted data, API contracts, or UI output.

Source task: `split-chat-and-scrollable.task.md`.

I read `CLAUDE.md` first, then reviewed the current code. The repository is no longer in the original state described by the task brief: most of the split has already been attempted, but there are now two parallel module layouts for both Chat and the scrollable page. This plan is therefore about finishing the refactor cleanly and removing duplicate/dormant paths, not starting from the old 524-line / 463-line files.

## Constraints

- Do not redesign the Chat UI or `/scrollable` layout.
- Do not change the `@/components/Chat` public import path.
- Do not change the default export shape for Chat.
- Do not change `STORAGE_KEYS.CHAT_HISTORY` or the persisted message schema.
- Do not change `/api/chat` or `/api/feedback` request/response behavior.
- Do not introduce dependencies.
- Do not do unrelated styling cleanup.
- Keep files under the repo's 300-line convention.
- Use CSS variables and existing utility classes for colors.
- Preserve dynamic imports for heavy/client-only components.

Active import resolution currently uses the file:

That file is only 85 lines and imports from the folder:

A second, mostly duplicate Chat implementation also exists:

- `src/components/Chat/index.ts`
- `src/components/Chat/Chat.tsx`
- `src/components/Chat/Chat.hooks.ts`
- `src/components/Chat/Chat.storage.ts`
- `src/components/Chat/Chat.types.ts`

Important detail: because `src/components/Chat.tsx` exists, imports like `dynamic(() => import('@/components/Chat'))` resolve to the file, not the folder barrel. The folder `index.ts` is not the active public entry yet.

The active implementation has the better runtime safety:

- `useChatSession.ts` keeps `messagesRef` in sync and uses it for delayed/imperative sends.
- It preserves hydration gating before saving stored messages.
- `ChatMessageList.tsx` uses `useHasMounted()` to avoid timestamp hydration mismatches.
- It keeps `onReady` wrappers stable through refs.

The inactive folder implementation has the target public shape but should not be adopted wholesale without review:

- `Chat.hooks.ts` initializes from storage in the state initializer and saves on every message change, which loses the active hydration guard behavior.
- `parts/MessageItem.tsx` formats timestamps immediately and does not use the mounted guard.
- `parts/CopyButton.tsx` uses `hover:bg-[var(--glass-bg)]` instead of the active `hover:bg-[var(--glass-bg-strong)]`.
