# Portfolio Chatbot Architecture

## Goal

The portfolio chatbot should answer accurately from Kevin Jiang's public portfolio data, avoid invented claims, and fail safely when live model access is unavailable.

## Current Implementation

- Source of truth: `src/content/portfolio.json`, shaped through `src/lib/projects-data.ts`.
- Grounding layer: `src/lib/chat-knowledge.ts` builds searchable profile, skill, project, experience, education, and contact sections.
- Guardrails: the API blocks private-data, credential, and prompt-extraction requests before model calls.
- Retrieval: each user message retrieves the most relevant portfolio sections and sends only those facts to the model.
- Provider: `/api/chat` uses Gemini or OpenAI after shared retrieval. Provider selection is controlled by `CHAT_PROVIDER`, defaulting to Gemini when `GOOGLE_GENERATIVE_AI_API_KEY` is available, then OpenAI when `OPENAI_API_KEY` is available.
- Fallback: without a configured provider key, the route returns deterministic demo-mode answers from retrieved portfolio context.

## Request Flow

```text
Chat UI
  -> POST /api/chat
    -> request validation
    -> message guardrails
    -> local portfolio retrieval
    -> default context fallback for greetings or low-signal allowed prompts
    -> instruction builder
    -> provider adapter
       -> Gemini generateContent, or
       -> OpenAI Responses API, or
       -> local demo response
    -> JSON response
```

A normal live response makes one external model call. Retrieval does not call a database or embedding service; it runs in-process against the local portfolio payload.

## Retrieval Layers

1. `portfolio.json` is imported as structured data.
2. `PROJECTS` from `src/lib/projects-data.ts` normalizes project fields used across the site.
3. `chat-knowledge.ts` converts portfolio data into knowledge sections:
   - `profile`
   - `skills`
   - `experience`
   - `education`
   - `contact`
   - `project:<id>` for each project
4. The user message is normalized and tokenized.
5. Each knowledge section is scored:
   - exact keyword token match: higher weight
   - content substring match: lower weight
6. The highest-scoring sections are formatted as verified context.
7. If an allowed prompt has no useful tokens, such as a greeting, the route uses default profile/skills/experience/contact context.

This is retrieval-augmented generation without embeddings. It is intentionally lexical because the current source data is small, structured, and regenerated by portfolio-sync.

## Guardrail Layers

Guardrails are deliberately split:

- Request limits prevent oversized payloads and long histories.
- Pre-model policy checks block secrets, credentials, private data requests, and prompt-extraction attempts.
- Topic checks keep the assistant scoped to Kevin's public portfolio.
- Model instructions require answers to use only verified retrieved context.
- Demo mode uses deterministic local responses when no provider is configured.

The model is not the only safety layer. Unsafe or off-topic requests should be rejected before Gemini or OpenAI receives them.

## Provider Selection

Provider resolution happens in `/api/chat`:

- `CHAT_PROVIDER=google` or `CHAT_PROVIDER=gemini` requires `GOOGLE_GENERATIVE_AI_API_KEY` or `GEMINI_API_KEY`.
- `CHAT_PROVIDER=openai` requires `OPENAI_API_KEY`.
- If `CHAT_PROVIDER` is unset, the route prefers Gemini when a Google key exists, then OpenAI when an OpenAI key exists.
- If the selected provider has no key, the route returns demo-mode answers from local retrieval.

Both live providers receive the same retrieved context and behavioral instructions. Provider adapters only translate the shared prompt into each API's request shape.

## Why This Instead Of Hosted Vector Search Now

OpenAI file search with vector stores is the right next step when the knowledge base grows into many documents, PDFs, long READMEs, or private notes. For the current site, the source data is small and structured, so local retrieval is faster, cheaper, easier to test, and easier to keep deterministic.

## Production Checklist

- Set `GOOGLE_GENERATIVE_AI_API_KEY` in the deployment environment for the recommended low-cost Gemini path.
- Optionally set `CHAT_PROVIDER=google` or `CHAT_PROVIDER=openai`.
- Optionally set `GEMINI_CHAT_MODEL`; default is `gemini-2.5-flash`.
- Optionally set `OPENAI_API_KEY` and `OPENAI_CHAT_MODEL`; OpenAI default is `gpt-5.4-mini`.
- Keep `src/content/portfolio.json` accurate through manual edits or `npm run sync-portfolio`.
- Add new factual claims to portfolio data before expecting the chatbot to use them.
- Review negative feedback from `/api/feedback` to find missing facts or overly strict guardrail cases.

## Upgrade Path

Move to hosted file search when portfolio-sync starts ingesting richer project artifacts. The natural feed is a generated markdown or JSONL file per project containing `.portfolio.json`, README summaries, selected links, and media captions, uploaded to a vector store during deploy or sync.

Until then, keep factual improvements in `src/content/portfolio.json` or in project `.portfolio.json` files. The chatbot should not be taught facts through prompt text that are absent from the source data.
